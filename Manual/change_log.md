# 3 August 2026 -- Richard
- The ```sigmoid``` antecedent lake volume curve in the [lake config file](SubDocs/config/LakeConfig.md) is evaluated as ```log10 V(z) = A / (H + exp(-k (z - z0))) + log10(Vf)```, but ```A``` was never a config key - it was hard coded as ```log10(Vc)```. That is correct for the curves taken from the original ADV assessment workbooks, where ```H``` (the "height adjustment factor") was hand-tuned until the curve passed through a chosen midpoint volume, and where ```Vc``` is therefore ```10 ** A``` rather than the true ceiling. It is wrong for a curve fitted as a standard logistic between a floor and a ceiling, which sets ```H = 1``` and needs ```A = log10(Vc) - log10(Vf)```.
- **Bryan now computes ```A``` from the ```Vf``` and ```Vc``` already in the file, using ```H``` to tell the two conventions apart.** Where ```H``` is 1, or is not given at all, the curve is read as the standard logistic and ```A = log10(Vc) - log10(Vf)```, so the ceiling is exactly ```Vc```. Where ```H``` is anything else the curve is read the original way, with ```A = log10(Vc)```. ```H``` may now be left out of the config file, as it does nothing for a fitted curve.
- **Old models are unaffected.** Their ```H``` is above 1, so they are read exactly as before and results do not move. This split is safe because ```H = 1``` can never be a deliberate hand-tuned curve: in that convention it puts the upper asymptote at ```Vc * Vf```, which needs a floor of 1 ML to mean anything, and any realistic floor gives an ```H``` well above 1 (a 10,000 ML floor under a 140,000 ML ceiling gives 4.6).
- Getting the convention wrong fails silently, which is why it is worth knowing about. At Callide an ```H = 1``` file read the old way gave an ADV ceiling of 1.5 billion ML against a full supply volume of 129,041 ML. The run completed, but most realisations started above the top of the storage curve, so the lake level pinned at the top of the ```.els``` and the lake level frequency curve came out blank while the inflow curve still looked perfectly sensible.
- ```A``` can also be set explicitly in the ```coefficients```, overriding the rule above, for a curve that is neither convention. It is not needed for either of the standard cases and should normally be left out.
- Bryan now prints the resolved ```A```, which convention it came from, and both asymptotes of the curve when it loads a sigmoid layer. If the resulting ceiling lands more than a factor of two above ```Vc``` it also prints a warning saying what to check. Watch for this line when picking up an unfamiliar model.
- The ```Input MCDF``` key in the simulation list (```reservoir routing``` method) now accepts a ```.parquet``` file as well as a ```.csv```, matching the ```Inflow``` key, which already did. Both go through a shared reader. Previously an mcdf written as parquet by the Monte Carlo run had to be converted to csv by hand, and pointing at it directly failed with a ```UnicodeDecodeError```. Parquet needs ```pyarrow``` installed.

# 6 August 2026 -- Richard
- **Added the PMP embedded burst screen.** Every simulation that sets up extreme rainfall now checks each temporal pattern for embedded bursts that would exceed the PMP for their own sub-duration, and reports the result near the top of the simulation log. This is a different question from the sub-burst neutrality check: neutrality asks whether embedded bursts occur *more often* than the IFD statistics imply, and is answered from the simulated realisations; the PMP screen asks whether a pattern can produce a sub-burst above the physical envelope at all, and is answered from the patterns and the PMP depth-duration curve alone.
- The screen is a pre-simulation check because the breach condition does not depend on the sampling. For a pattern holding a fraction ```r_s``` of its depth in the worst window of sub-duration ```s```, the sub-burst reaches the sub-duration PMP once the burst depth exceeds ```D_crit = PMP_s / r_s```. Above the PMP anchor the sampled depth and the admissible bound (```PMP_s * max(1, depth / PMP_d)```) scale together, so the exceedance ratio stops growing and holds at ```PMP_d / D_crit```. That ratio is the ceiling on severity however far the sampling extrapolates past the AEP of the PMP, and a pattern with ```D_crit >= PMP_d``` never breaches at any depth.
- The report gives, for each pattern that can breach, the binding sub-duration, ```r_s```, ```D_crit```, the AEP at which the burst depth reaches it, the exceedance ratio at and above the anchor, and the share of that pattern set's sampled realisations above ```D_crit```. Patterns that can only breach beyond the sampled AEP range are reported as a ```CHECK```; patterns that breach inside it as a ```WARNING```.
- **Climate change is handled by uplifting the PMP depths along with the sampled depths**, each at its own duration's factor, since the rainfall uplift scales a duration's whole frequency curve by the same amount at every AEP. The factors used are printed above the table. A uniform uplift would leave both the exceedance ratio and the engagement AEP untouched; because the factor is duration dependent (15%/°C at 1 hour easing to 8%/°C at 24 hours and beyond) a sub-duration is uplifted more than its parent, so the ratio becomes ```r_s × PMP_d·u(d) / (PMP_s·u(s))``` and warming **eases** the bound. A climate change run is not the adverse case for this check.
- ARR areal/point as well as GSDM/GTSMR patterns are screened, each over the AEP window it is actually sampled in. For a small catchment the ARR patterns cannot get near the PMP and the screen is inert for them; the case worth watching is a catchment large enough that the [AEP of the PMP](SubDocs/config/IFDFilesConfig.md) is only half a decade beyond the 1 in 2,000 changeover, where the top of the ARR range does approach the PMP.
- **Nothing is filtered.** The screen only reports. The duration and warming level are not kept - blank means read it from the database name.

# 11 September 2026 (5) -- Richard
- **A URBS model can now have more than one dam with its own antecedent storage.** A regional model routes through several, and each needs its own starting level. Everything about a dam is already on its ```DAM ROUTE``` line - the full supply level, the storage curve, and the name of the environment variable URBS reads the starting level from - so the model config only says which extra dams to set and where each one's lake config is: ```"additional_dams": [{"location": "KROOMBIT", "lake_config": "..."}]```. The variable name is deliberately **not** configurable: it comes off the vec, which is the only place it can be right.
- **Both dams in the regional Callide model shipped with ```il=initial_lake_level```**, so one ```set``` statement drove both and Kroombit started every event at Callide's level. The model runs and says nothing. Two dams sharing one variable is now refused, by name, with what to do about it; Kroombit's line reads ```il=kroombit_lake_level```.
- **Fixed: ```find_dam_routing_line``` could not see an indented ```DAM ROUTE```.** It matched on ```line.startswith```, and a dam nested inside a ```STORE.```/```GET.``` block is indented - which is how the regional model routes Kroombit, so the line was invisible and the dam reported as missing from the vec.
- **Fixed: setting a lake level twice appended instead of replacing, once there were two dams.** The old code inspected only ```header[-1]```; with a second dam's line after it, re-setting the first appended a duplicate and cmd.exe takes the last one. Replacement is now by variable name. The ```ADV_below``` volume method goes through the same helper.
- The main dam's variable is read from its own ```il=``` token too, defaulting to ```initial_lake_level```, so a model that names it something else works without a config key.
- **The downstream storm generator now writes a batch file per event, and can run URBS.** The batch file carries the URBS command line and a ```set``` statement for every dam's starting lake level, and is **always** written - it is the record of what the run was, so a run done by hand later is the run that was described. ```--run-urbs``` executes each one as it is written; without it nothing is run, which is usually what you want at minutes per event on a regional model. ```--dry-run``` with ```--run-urbs``` is refused.
- Every dam's antecedent storage comes from the event's single ```lake_z``` through that dam's own volume exceedance curve. The main dam is the exception: where the realisation recorded an ```ADV``` that is the storage it actually had, and it is used in preference to re-reading the curve.
